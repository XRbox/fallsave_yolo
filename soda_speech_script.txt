📌 ส่วนที่ 1: MODELS (โมเดลที่เลือกใช้ และการแก้ปัญหา Class Imbalance)
[เวลา: ~1 นาที]
================================================================================
(ชี้ที่หัวข้อ Vision AI & Classifier)

"ในส่วนของ Model เราเลือกใช้สถาปัตยกรรมแบบ Hybrid ที่ทำงานร่วมกัน 2 ระดับครับ:

1. ระดับแรก Vision Model: เราใช้ 'YOLO11n-Pose'
   ทำหน้าที่ตรวจจับ 17 พิกัดข้อต่อร่างกายมนุษย์แบบ Real-Time เหตุผลที่เลือกใช้ตัว Nano เพราะมีขนาดเล็กมาก 
   ประมวลผลได้เร็วสูง และรันบนคอมพิวเตอร์ทั่วไปหรือ CPU ได้อย่างลื่นไหลโดยไม่ต้องพึ่งการ์ดจอยักษ์ครับ

2. ระดับที่สอง Machine Learning Classifier: เราเลือก 'Balanced Logistic Regression'
   ทำหน้าที่จำแนก 3 คลาส คือ Normal, Falling, และ Lying
   • ปัญหาสำคัญของข้อมูลการล้ม คือ 'Class Imbalance' เพราะในชีวิตจริง คนเรายืนเดินปกติมากกว่าการล้มมหาศาล 
     เราจึงใช้เทคนิค 'class_weight=balanced' เพื่อถ่วงน้ำหนักการเรียนรู้ให้โมเดลให้ความสำคัญกับคลาสล้มมากขึ้น
   • เราได้เปรียบเทียบกับ Random Forest และ Baseline อื่นๆ แล้วพบว่า Logistic Regression ตอบโจทย์ระบบ Real-Time มากที่สุด 
     เพราะใช้เวลาประมวลผลระดับไมโครวินาที ไม่กิน CPU และส่งค่า Softmax Probabilities ที่นิ่งสม่ำเสมอ 
     เพื่อส่งต่อไปยังอัลกอริทึมการตัดสินใจเชิงเวลาครับ"

📌 ส่วนที่ 2: ALGORITHMS (4-State Temporal Finite State Machine)
[เวลา: ~1.5 นาที]
================================================================================
(ชี้ที่แผนภาพ State Diagram 4 สถานะ)

"ทำไมเราถึงไม่ใช้แค่ AI ทายผลแล้วเตือนทันที? 
เพราะในชีวิตจริง ถ้าคนแค่ก้มเก็บของ หรือทิ้งตัวนั่งลงโซฟาเร็วๆ AI อาจมองว่าล้ม ซึ่งจะเกิด False Alarm บ่อยมาก
เราจึงออกแบบ 'Temporal State Machine 4 สถานะ' มาเป็นตัวคุมตรรกะเวลาครับ:

1. สถานะ NORMAL: ผู้ใช้ใช้ชีวิต ยืน เดิน นั่ง ตามปกติ
2. สถานะ FALLING_SUSPECTED: เมื่อ AI ตรวจพบความน่าจะเป็นของการล้ม P(falling) ≥ 0.45 
   ระบบจะเข้าสู่โหมดเฝ้าระวังชั่วคราว
3. สถานะ GROUND_CHECK: เมื่อคนลงไปนอนติดพื้น P(lying) ≥ 0.35 หรือตรวจไม่พบคีย์พอยต์หลังล้ม 
   ระบบจะเริ่มนับเวลาถอยหลังทันที เพื่อดูว่าคนนอนนิ่งหรือลุกขึ้นมา
4. สถานะ FALL_CONFIRMED: หากนอนนิ่งค้างอยู่กับพื้นครบ 2.0 ถึง 2.5 วินาที 
   ระบบจะยืนยันการล้มจริง ส่งเสียงไซเรนฉุกเฉินและเซฟภาพ Snapshot เป็นหลักฐานทันทีครับ

นอกจากนี้ เรายังมีตรรกะ 'Quick Recovery & Anti-False Alarm':
หากผู้ใช้เพียงแค่สะดุด หรือนั่งลงเร็ว แล้วสามารถลุกขึ้นยืนเองได้ภายในเวลาที่กำหนด 
ระบบจะยกเลิกการเตือนและรีเซ็ตกลับสู่ NORMAL ทันทีครับ 
และในระดับโค้ดดิ้ง เราได้เขียน Unit Tests ครอบคลุมการทำงานของ State Machine ถึง 11 Test Cases 
และผ่านการทดสอบ 100% ทั้งหมดครับ"

📌 ส่วนที่ 3: ACCURACY & BENCHMARK RESULTS (ผลการทดสอบเชิงสถิติ)
[เวลา: ~1.5 นาที]
================================================================================
(ชี้ที่ตารางผลประเมิน URFD Test Set)

"มาดูในส่วนของความแม่นยำและการประเมินผลครับ เราวัดผล 2 ระดับอย่างเข้มงวด:

ระดับแรก: ผลทดสอบบน Test Set ของชุดข้อมูลมาตรฐาน URFD (ซึ่งเป็นคลิปที่ไม่เคยผ่านตาโมเดลมาก่อน)
• เราทำ Overall Accuracy ได้สูงถึง 93.32%
• ด้านความปลอดภัย ซึ่งวัดจาก Falling Recall ทำได้ 82.00% (ตรวจจับจังหวะล้มได้ 41 จาก 50 เหตุการณ์)
• ด้านการป้องกันการเตือนมั่ว Normal Specificity สูงถึง 94.33%
• และมีค่า Macro F1-Score อยู่ที่ 83.49% ครับ"

(ชี้ที่ตาราง Benchmark วิดีโอจริง 2,014 คลิป)

"ระดับที่สอง: การ Benchmark ขนาดใหญ่กับชุดวิดีโอภายนอก (VideoDataset) รวม 2,014 คลิป 
(แบ่งเป็นคลิปล้ม 997 คลิป และกิจกรรมทั่วไป 1,017 คลิป) โดยระบบแบ่งเป็น 2 โหมด:

1. 'โหมดเฝ้าระวัง (Suspected Mode)':
   • มี Accuracy รวม 88.28% 
   • แต่จุดเด่นคือ Fall Recall สูงถึง 96.99%! (ตรวจจับการล้มได้ถูกต้องถึง 967 จาก 997 คลิป พลาดเพียง 30 คลิปเท่านั้น) 
     เหมาะสำหรับโหมดความปลอดภัยสูงสุด

2. 'โหมดเข้มงวด (Strict Mode - Confirmed Fall)':
   • มี Accuracy รวม 81.43%
   • และจุดเด่นคือ ADL Specificity สูงถึง 99.21%! โดยมี Precision สูงถึง 98.75%
   • หมายความว่าจากกิจกรรมทั่วไป 1,017 คลิป ระบบมี False Alarm หลุดเตือนผิดพลาดเพียงแค่ 8 ครั้งเท่านั้นครับ!

ตัวเลขเหล่านี้พิสูจน์ให้เห็นว่า การผสาน Machine Learning ร่วมกับ State Machine ช่วยแก้ปัญหา False Alarm 
ในขณะที่ยังรักษาความไวในการตรวจจับคนล้มได้อย่างมีประสิทธิภาพสูงครับ"

Q: ทำไมเลือก Balanced Logistic Regression ทำไมไม่ใช้โมเดล Deep Learning (เช่น LSTM หรือ Transformer)?
A: "เพราะหัวใจของระบบเราคือการรันแบบ Real-Time บนคอมพิวเตอร์ทั่วไปครับ Deep Learning ต้องการ GPU สูง 
    แต่การใช้ YOLO-Pose สกัด Keypoint แล้วลดมิติมาเป็น Biomechanical Features ทำให้เราสามารถใช้ Logistic Regression 
    ที่ประมวลผลเร็วระดับไมโครวินาที และปล่อยให้ State Machine คอยจัดการเรื่องมิติของเวลาแทน ทำให้ได้ความแม่นยำสูง 
    แต่ประหยัดทรัพยากรเครื่องมากกว่าอย่างมหาศาลครับ"

Q: ทำไม Recall ใน Strict Mode ได้ 63.29% แต่ใน Suspected Mode สูงถึง 96.99%?
A: "เพราะ Strict Mode มีเงื่อนไขที่เข้มงวดมากครับ คือต้องเห็นคนนอนติดพื้นค้างต่อเนื่องครบ 2.5 วินาที 
    แต่ในวิดีโอ Benchmark บางคลิป คนล้มแล้วกลิ้งหลุดออกจากขอบกล้อง หรือคลิปตัดจบก่อนครบ 2.5 วินาที 
    ทำให้ใน Strict Mode ยังไม่ทัน Trigger แต่ใน Suspected Mode ระบบจับจังหวะล้มได้ทันทีตั้งแต่แรก 
    ซึ่งสูงถึง 96.99% แสดงว่าโมเดลตรวจจับการล้มได้เกือบทั้งหมดครับ"
